---
title: 歌曲分段
description: 把歌词行归入歌曲的各个段落并标注其类型
---

歌曲分段（Section）包含歌曲某一部分的歌词行，例如主歌或副歌。使用 `<div>` 分组歌词行，并用 `itunes:songPart` 属性标注该段落的类型。

## 分组行文

当歌曲进入不同段落时开启新的 `<div>`。每个分段的时间区间应当紧扣其包含的歌词行。示例歌词为虚构内容：

```xml
<body dur="00:20.000">
  <div begin="00:00.000" end="00:08.000" itunes:songPart="Verse">
    <p begin="00:01.000" end="00:04.000">I left my coat</p>
    <p begin="00:04.000" end="00:08.000">By the open door</p>
  </div>
  <div begin="00:08.000" end="00:20.000" itunes:songPart="Chorus">
    <p begin="00:08.000" end="00:14.000">And I never went back</p>
    <p begin="00:14.000" end="00:20.000">I never went back</p>
  </div>
</body>
```

分组结构是播放器排版渲染的依据：它标明前一个段落在此结束、下一个段落在此开始。属性标签则指明该段落的具体类型。

## 给部分命名

播放器能够识别以下八个属性值：

| 值 | 用于 |
| --- | --- |
| `Intro` | 前奏段落，位于第一遍主歌之前且包含人声 |
| `Verse` | 主歌叙事段落，每次出现时歌词均有变化 |
| `Pre-Chorus` | 导歌（预副歌），主歌与副歌之间的情绪递进段落 |
| `Chorus` | 副歌，歌曲中主要反复出现的段落 |
| `Refrain` | 叠句，反复出现但并非完整副歌的单行或短句 |
| `Bridge` | 桥段（过门），形成听觉反差的对比段落，通常在歌曲后半段出现一次 |
| `Outro` | 尾奏段落，歌曲的收尾部分 |
| `Instrumental` | 纯器乐段落，没有主唱人声 |

这些属性值不区分大小写，因此 `chorus` 与 `CHORUS` 都会被解析为副歌。建议通篇按上表所示的标准大小写书写，保持文件风格一致。

此列表之外的值均无法被播放器识别。歌词行依然会正常显示，但播放器不会将该分段识别为特定歌曲段落。与其为 `<div>` 编造自定义值，不如直接省略该属性。

## 用实际对应的标签

<Callout type="warn" title="不是每个分段都是主歌">
有些厂牌与发行商不论实际曲式如何，把歌曲中的每个分段一律标记为 `Verse`。播放器虽然不会报错，但这种不良习惯会导致歌词文件记录了歌曲根本不存在的错误结构。
</Callout>

根据实际演唱的曲式选择准确的属性值。重复三次的副歌每次都应标注为副歌，引向副歌的递进段落是预副歌（Pre-Chorus），而不是主歌的一部分。

如果无法确定某个段落的属性，直接在 `<div>` 上省略 `itunes:songPart`。缺少标签不会造成误导，错误的标签反而会凭空记录不真实的曲式结构。

分段划分同样应实事求是。不要为了回避标签选择而把主歌和副歌塞进同一个 `<div>`，也不要随意把同一个段落拆散到多个分段中。

## 器乐部分

`Instrumental` 用于描述歌曲中没有主唱人声的段落。它并不是用来命令播放器在行间显示倒计时圆点的；Apple 播放器会自动根据歌词行之间的时间空隙推算倒计时。标注分段应当忠实反映录音结构，而不是为了迎合播放器的某种视觉呈现。
