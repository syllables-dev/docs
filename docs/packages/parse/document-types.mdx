Import these types from `@syllables-dev/parse`. The tables come directly from the installed package's `.d.ts` files during the documentation build.

```ts
import type { LyricsDocument, LyricsLine, Syllable } from "@syllables-dev/parse";
```

## LyricsDocument

The document is plain JSON. All timestamps are absolute integer milliseconds, including syllable times; they are not relative to the containing line. A source offset is already applied by the reader and must not be added again.

## LyricsLine

`p` is the primary vocal track and `b` is the backing track. Each contains timed syllables. Translation and pronunciation tracks are keyed by BCP 47 language tags.

<auto-type-table path="../../../../node_modules/@syllables-dev/parse/dist/types.d.ts" name="LyricsLine" />

## Syllable

Text includes meaningful whitespace. Concatenate adjacent syllables with `join("")`, not `join(" ")`.

When `content` is present, it stores the authoritative ordered mix of strings and nested syllables. `text` is the visible text derived from that structure. Editing only `text` does not replace the structured content.

<auto-type-table path="../../../../node_modules/@syllables-dev/parse/dist/types.d.ts" name="Syllable" />

### SyllableContent

`content` holds `SyllableContent[]`, and each item is either a `Syllable` or a `string`. A string is literal text at that position; a nested syllable carries its own timing and can nest further.

## Translations

### LyricsTranslation

Translations normally carry text in `p` and optional backing text in `b`. Apple TTML can retain structured words and timing as well. When `pWords` or `bWords` exists, it is authoritative over the corresponding flattened string.
