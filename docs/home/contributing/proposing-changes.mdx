---
title: Proposing changes
description: Prepare a focused documentation or project change.
---

Explain the problem before the solution. Link to the affected page or project, describe the current behavior, and show what the change would improve.

## Documentation changes

Keep each proposal focused on one topic. Include the suggested wording and an example when a rule could be interpreted in different ways. Cite the source for factual corrections, and preserve the original lyric text and timing in existing examples.

## Code changes

Follow the repository's setup and contribution instructions. Explain how the change was checked, and include reproduction steps for a bug fix. Keep unrelated formatting or refactoring out of the pull request.

## Larger proposals

For a new feature or a change to an established convention, start a discussion before preparing a large patch. Describe the use case, alternatives, and any effect on existing files or users.
