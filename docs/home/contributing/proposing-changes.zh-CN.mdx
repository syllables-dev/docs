---
title: 提出修改建议
description: 聚焦具体问题，准备清晰明确的文档或项目修改提案。
---

提方案前先说清问题。附上受影响的页面或项目链接，描述当前的行为表现，并说明改动后能带来哪些改进。

## 文档修改

每次提案只聚焦一个具体主题。若某项规则可能产生不同理解，请提供建议的文字表述和具体例子。事实性勘误需注明出处；调整已有示例时，歌词原文与时间数据必须保持原样。

## 代码修改

遵循对应仓库的开发环境配置与贡献指南。提交时说明改动的验证方式；若是修复缺陷，还需附上清晰的复现步骤。避免在同一个 pull request 中夹带无关的格式调整或代码重构。

## 较大提案

如果是新增功能或调整既有规范，请在动手编写大体量补丁前先发起讨论。说明具体的使用场景、权衡过的其他方案，以及对现有文件或用户的影响。
