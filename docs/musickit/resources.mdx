---
title: Resource model
description: Catalog types, relationships, and views
---

Fetch a catalog resource, its related resources, or a view with these paths:

```http
GET /v1/catalog/{storefront}/{type}/{id}
GET /v1/catalog/{storefront}/{type}/{id}/{relationship}
GET /v1/catalog/{storefront}/{type}/{id}/view/{view}
```

A relationship returns related resources of another type. A view returns an editorially assembled shelf, which is why views exist only on the types that have pages built around them.

The tables below list the resource types, relationships, and views covered by this reference. Availability can vary by resource and storefront.

## Resource types

Twenty-one types are addressable under `/v1/catalog/{storefront}/{type}/{id}`:

| Type | Type | Type |
| --- | --- | --- |
| `albums` | `apple-curators` | `artists` |
| `audio-analysis` | `classical-works` | `concerts` |
| `curators` | `genres` | `music-movies` |
| `music-videos` | `playlists` | `record-labels` |
| `songs` | `station-genres` | `stations` |
| `tv-episodes` | `tv-seasons` | `tv-shows` |
| `uploaded-audios` | `uploaded-videos` | `venues` |

`genres` answers 500 `Error extracting the attribute 'parentId' for genres` for an id that does not exist, rather than 404. Read genres through [`/v1/catalog/{storefront}/genres`](/musickit/reference/catalog/getCatalogGenres) instead.

Library resources are a separate set, reached under `/v1/me/library/{collection}`: `albums`, `artists`, `music-videos`, `playlist-folders`, `playlists`, `songs`. Their resource types carry a `library-` prefix, so `/v1/me/library/songs` returns `library-songs`.

## Artist canvas resources

Artist responses can also contain `canvas-shelves-group`, `canvas-shelves-collection`, `canvas-shelves-header`, `canvas-shelves-text`, and `canvas-shelves-client-marker`. These describe a page layout and refer to catalog items through relationships. See [Artist details and shelves](/musickit/artist-details) for the request options and how to traverse the response.

## Relationships

Requesting a relationship a type does not declare answers `40008`. Requesting one it declares but has nothing for answers 404 `40403 No related resources`, which is not an error about the relationship existing.

| Type | Relationships |
| --- | --- |
| `albums` | `artists`, `genres`, `library`, `record-labels`, `tracks`, `works` |
| `apple-curators` | `events`, `playlists` |
| `artists` | `albums`, `genres`, `music-videos`, `playlists`, `songs`, `station` |
| `audio-analysis` | Not listed. |
| `classical-works` | `composers` |
| `concerts` | `artists`, `playlists`, `venues` |
| `curators` | `playlists` |
| `genres` | Not listed. |
| `music-movies` | `genres` |
| `music-videos` | `albums`, `artists`, `genres`, `library`, `songs` |
| `playlists` | `curator`, `library`, `tracks` |
| `record-labels` | Not listed. |
| `songs` | `albums`, `artists`, `audio-analysis`, `composers`, `credits`, `genres`, `library`, `lyrics`, `music-videos`, `station`, `syllable-lyrics` |
| `station-genres` | `stations` |
| `stations` | `events` |
| `tv-episodes` | `genres`, `seasons` |
| `tv-seasons` | `episodes`, `genres` |
| `tv-shows` | `tv-seasons` |
| `uploaded-audios` | `artists`, `curator` |
| `uploaded-videos` | `artists`, `curator` |
| `venues` | Not listed. |

Three of these relationships are worth calling out.

`songs/lyrics` and `songs/syllable-lyrics` return the same lyric in two different timings. `lyrics` is line-timed (`itunes:timing="Line"`), `syllable-lyrics` is word-timed (`itunes:timing="Word"`). Both return TTML in `attributes.ttml` and both need a subscribed account; without one they answer 404 `40403`, not 403.

`library` maps a catalog resource onto the signed-in account's copy of it, which is how the client knows whether an album is already added.

## Views

Views return curated collections associated with a resource, and exist only on the types that have pages built around them. Each endpoint page lists the views it accepts.

A view can be requested on its own path or alongside the resource:

```http
GET /v1/catalog/us/artists/1419227/view/top-songs
GET /v1/catalog/us/artists/1419227?views=top-songs,similar-artists
```

The two forms validate differently. An unknown name in the path segment answers `40008`; an unknown name in the `views` parameter is dropped and the response is still 200. `genres` and `station-genres` do not reliably reject unknown view names either way, so a successful response alone does not establish view support.
