---
title: Authentication
description: Tokens and headers for API requests
---

Catalog requests require a developer token issued for the web player. Personalized requests also require a music user token obtained through sign-in. Each endpoint lists its authentication requirements.

## Request headers

| Header | Value | Required for |
| --- | --- | --- |
| `Authorization` | `Bearer <developer token>` | Media API requests. |
| `Origin` | `https://music.apple.com` | Media API requests. |
| `Referer` | `https://music.apple.com/` | Include alongside `Origin`. |
| `Media-User-Token` | `<music user token>` | Personalized requests and `/v1/play/assets`. |
| `X-Apple-Music-User-Token` | `<music user token>` | Authenticated playback requests to `play.itunes.apple.com`. |

## Optional headers

`X-Apple-Client-Version` identifies the app build. It is optional and is not an authentication credential.

## Token scope

Send a valid, unexpired JWT issued for `amp-api.music.apple.com`. Developer tokens issued for the public API at `api.music.apple.com` are not interchangeable with this host's credentials. Marketing requests to `amp-api-edge.media.apple.com` use a separate token scope.

The music user token comes from the sign-in flow; it is not a token you mint. Catalog reads can also require it for personalized filters or subscription content. Check the endpoint's requirements rather than relying on its path alone.

## Origin is part of the credential

The web player token is scoped to `apple.com` through its `root_https_origin` claim. The origin must use HTTPS on `apple.com` or one of its subdomains. A missing or invalid origin returns 401 with an empty body, even when the token is valid.

Server-side requests must also supply `Origin`. `Referer` does not replace it and is not checked independently.
